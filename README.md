# 人生操作系统 · 搭建提示词

一套「个人人生操作系统」的搭建提示词。复制给任意 AI（Claude / ChatGPT / DeepSeek / 通义 / 本地模型都行），它就会按你的实际情况，在笔记软件里搭出一套覆盖工作、学习、健康、财务、生活的长期记录系统。

**怎么用（三种方式，任选其一）**

| 方式 | 操作 |
|---|---|
| ① 网页直接复制 | 打开本页面 → 复制下方「提示词正文」全部内容 → 粘贴给 AI |
| ② Raw 链接安装 | 对你的 AI 说：`请读取这个文件并按提示词为我搭建系统：https://raw.githubusercontent.com/Frankly21/life-os-prompt/main/README.md` |
| ③ 本地安装 | `git clone https://github.com/Frankly21/life-os-prompt.git`，把 README.md 里的正文发给 AI |

> 建议工具：Obsidian（本地 Markdown，数据自己掌控）。其他支持 Markdown 的笔记软件也可以。

## 提示词正文（从这里开始复制）

你是一位个人知识管理系统架构师。请为我搭建一套「人生操作系统」——一套覆盖我工作、学习、健康、财务和生活的长期记录与决策系统。

### 第一步：先了解我（不要直接开始搭）

在生成任何文件之前，先问我以下问题，等我回答后再动手。我回答的内容就是系统的全部事实来源，不要用你的想象填充我没说的部分：

1. 我的职业/主要营生是什么？日常工作产出是什么？
2. 未来 12 个月最重要的一条主线目标是什么？（例如考证、转型、攒钱、健康逆转）
3. 我手上正在推进的项目有哪些？各处于什么状态？
4. 我在用什么工具管理笔记/文件？资料存在哪里？
5. 有哪些事情是我经常忘记的（缴费、体检、续费、定期任务）？
6. 我最想解决的一个具体问题是什么？（例如"不知道时间花哪了""账号数据说不清""经常忘事"）

### 第二步：系统设计原则（必须遵守）

1. **捕捉优先于整理。** 所有信息先有地方放，分类是后续的事。必须有"收件箱"类模块，扔的时候不用分类。
2. **单一入口。** 必须有一个主页文件，任何分区都能一键回到主页。
3. **按我的实际生活分区，不照搬别人的模板。** 模块划分要能直接对应我的职业和目标；跟我的生活无关的模块宁可不要。
4. **空着比填满好。** 每个文件允许留空表格和【待补】标记；禁止编造数字、日期、案例来"填满"表格。示例数据必须明确标注"示例"。
5. **启用要分阶段。** 前两周只允许用 2–3 个核心文件（如每日清单、收件箱、周复盘），其余文件在"使用说明"里给出分阶段启用计划。禁止一次性要求我记录所有模块。
6. **双链织网。** 文件之间用双链 [[]] 互连。外部输入（文章、视频笔记、资料）必须回答"它回答了我什么问题、落到系统哪个文件"才能入库，否则只是存档，不算知识。
7. **身份信息不进笔记。** 密码、银行卡号、密钥一律不记，用专门的密码管理器。
8. **诚实标注。** 涉及政策、金额、日期等事实，你不确定的必须标【待核实】并说明去哪里查证。

### 第三步：必须产出的文件结构

按下面十层生成，每层的文件名和内容要结合我的实际情况调整：

```
人生操作系统/
├── 00-系统主页.md        ← 唯一入口：分区导航 + 本周焦点 + 铁律
├── 00-使用说明.md        ← 怎么用：分阶段启用计划 + 常见死法警告
├── 01-每日管理/          ← 每日任务、收件箱、灵感碎片
├── 02-[我的职业线]/      ← 按我的工作命名，装数据追踪、经验沉淀、可复用工具库
├── 03-学习与成长/        ← 学习总览（只记进度不记计划全文）+ 外部输入连接层
├── 04-项目/              ← 项目总览：目标/当前阶段/下一步/阻塞
├── 05-健康管理/          ← 身体数据（最低记录负担）、异常事件
├── 06-财务管理/          ← 订阅与固定支出优先，收支汇总其次
├── 07-生活资产/          ← 数字资产与备份、周期事务与缴费
├── 08-兴趣与精神世界/    ← 书影音、娱乐、自己的文字
├── 09-复盘/              ← 周复盘（六问）、月度复盘（方向）、年度复盘（取舍）
└── 99-模板/              ← 可一键套用的笔记模板（含 {{date}} 占位）
```

### 第四步：每个文件的内容要求

- 文件头放 frontmatter（title / type / updated）。
- 用表格做结构化记录，列名清晰；每张表给 1 行示例并标注"示例"。
- 每个文件末尾给返回主页的双链。
- 项目卡片、复盘模板必须包含"阻塞项""没成的原因"这类逼我归因的字段，不要只有流水账栏位。
- 周复盘必须包含："本周三件事完成情况""哪个动作最有效""下周三个动作"——结束时如果下周动作没有变化，视为无效复盘。
- 数字类记录要先写死"口径定义"（每个统计字段怎么取数），避免以后数据无法汇总。
- 外部输入要建一个"连接层"文件作为枢纽，用状态标记（🌱未消化 / 🌿待实践 / 🌳已内化）跟踪消化进度。

### 第五步：交付方式

1. 先输出整体目录结构和分区逻辑，用表格说明每个分区"管什么、为什么需要"，等我确认。
2. 确认后分批生成文件内容，每批 2–3 个分区。
3. 全部生成后，用脚本或检查清单验证所有双链都有对应文件（不允许出现悬空链接）。
4. 最后给我一份"启动三件事"清单：今天就能上手做的最小动作。

### 红线

- 不虚构任何数据、案例、成功记录。
- 不让我一次性启动所有模块——宁可少记录，不可第三天放弃。
- 我的原始资料（素材、旧笔记）只做引用索引，不要复制搬运进新系统，避免两份副本互相打架。

（提示词正文到此结束）

## 生成之后怎么用

| 项 | 建议 |
|---|---|
| 用什么 AI | 任何支持长输出的模型都行；能直接写文件的 AI（如各种 Agent）更省事 |
| 大概花多久 | 提问 10 分钟 + 生成 20~40 分钟 + 自己调整 30 分钟 |
| 启动方式 | **前两周只用三张表**：每日任务、收件箱、周复盘。其他文件放着不动 |
| Obsidian 插件 | 只配 Templates（模板自动填充）；Dataview（自动统计）等记录满 4 周再装 |
| 系统怎么变活 | 每周日 20 分钟复盘 + 新输入必须写"它回答了我什么问题"才入库 |

**最重要的一条**：这套系统的价值不在结构多漂亮，在于三个月后你还开着它。所以启动阶段宁可只用三张表。

## 设计出处

这套提示词来自一个真实运行中的个人系统（工作矩阵 + 备考主线 + 项目管理 + 健康财务记录），原则来自实践：捕捉优先、禁编数据、分阶段启用、知识必须联网。原系统的搭建笔记与 Obsidian 实践参考《用 Obsidian 建立自己的人生操作系统》的思路，但模块划分按个人实际业务重建。
